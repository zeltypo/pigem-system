# PIGEM recording script

**Current recording change:** Staff now compare the ID photos with the form by hand. In the three Agent scenes, show the original photos beside the entered details. Replace voice-over lines about automatic results with what the Agent sees and checks. The upload quality check still runs in the browser.

Use the three phone-sized views together when comparing applicants. Enlarge one view when the text needs to be read. Keep the same three application reference numbers throughout the recording. Use fictional applicant details.

## Groupmate 1 — Public website

**Record the homepage, banner, plans and contact links. Scroll slowly enough to read them.**

“Good day. We are presenting the PIGEM Internet Service Application System for Combined Facilities Support Services.

A customer can begin here on the public website. They can view the available fiber plans, compare the monthly price and speed, and read answers to common questions before applying.

For this example, we’ll choose Plan 1400. Clicking Apply for Plan 1400 takes us to the application form with that plan selected. The customer can still change the plan before continuing.”

**Record the About Us page, then return to the application form.**

“The About Us page gives customers more information about the company. The contact links are also available if they need help with their application.”

## Groupmate 1 — Application form

**Record three phone-sized views in one desktop frame. Use three separate applications. Enlarge the first view while explaining the form.**

“We’ll use three sample applicants to show how the system handles different situations. The first has details that match the submitted ID. The second has one incorrect ID number. The third has several details that need to be reviewed.

The layout adjusts to a phone screen, so customers can complete the form using their mobile device.”

**Record plan selection, personal information and date of birth.**

“The customer starts by choosing a plan and entering their personal information. Required fields must be completed before moving to the next step. If a value is missing or invalid, the form explains what needs to be changed.”

**Record the contact-information step, Send Email OTP, the verification email, and the verified indicator. Hide private inbox content.**

“Next, the customer enters an active Gmail address and mobile number. A verification code is sent to the email address. The customer enters that code here to confirm they can receive messages about their application.”

**Record the map, installation pin, address fields and landmark.**

“The customer then pins the installation location and completes the address. The landmark helps the team locate the property. The location still needs to be checked against the provider’s actual service availability.”

## Groupmate 1 — ID photos and submission

**Record the ID upload step. Select a clear front photo and a poor back photo. Keep both messages visible. Try Next while the poor photo is selected.**

“Here, the customer selects the ID type, enters the ID number, and uploads separate photos of the front and back.

Each photo has its own result. In this example, the front photo passes the quality check, but the back photo needs to be replaced. The message tells the customer what is wrong. The customer cannot continue with that photo.”

**Record replacing the poor photo and the updated message. Show the front message staying visible. Use clear replacements in all three submitted applications.**

“We’ll replace the back photo with a clearer copy. The result updates beside that photo. Both sides must pass the photo quality check before the customer continues.

The customer should still check that the printed details and all corners of the ID are visible.”

**Record the declaration, submission, reference number and confirmation email. Show the three references together.**

“After reviewing the information and accepting the declaration, the customer submits the application. The system gives the application a reference number and sends the account activation instructions.

We now have three submitted examples. We’ll follow these same applications in the Agent portal.”

## Groupmate 2 — Agent queue

**Record the Agent Dashboard and application queue. Keep the dashboard open while the documents are checked automatically. Show the queue results, then open an application for review.**

“This is the Agent Dashboard. The Agent can see the applications waiting for review and the applications already assigned to them.

The system checks pending documents automatically while the staff portal is open. The Agent can see the results in the application review, without starting a separate document check.

If a check is still running, the page shows that it is checking the documents. When the result is ready, it appears here.”

## Groupmate 2 — First application

**Record Applicant Profile and Installation Address, followed by Valid ID Photos and Document Check. Show the matching fields.**

“For our first applicant, the entered details match the information read from the document. The Agent can see the name, date of birth and ID number alongside the result.

The original front and back photos are available for inspection. When a cropped copy is available, the Agent can also use it to look at the document more closely.

These findings help the Agent review the application. The Agent still checks the requirements before moving it forward.”

## Groupmate 2 — Second application

**Record the second application’s ID number and its mismatch result. Enlarge this part of the screen.**

“In the second application, the customer entered an ID number that differs from the printed number. The result points out the mismatch while showing the other checked fields separately.

The Agent can choose the relevant correction and explain exactly what the customer needs to update. This helps the customer understand the issue without having to guess which part of the application is wrong.”

## Groupmate 2 — Third application and comparison

**Record the third application with several mismatched details. If using a Student ID without a printed birth date, show its actual result. Place the three result views side by side afterwards.**

“Our third applicant has more than one detail that needs attention. The Agent can review each finding and compare it with the uploaded document.

If a required detail is missing from the ID or cannot be read, the result shows that it needs verification. The Agent can inspect the original photo and request the appropriate update.

With the three examples beside each other, we can see how the results help the Agent focus on the specific issue in each application.”

## Groupmate 3 — Requesting and completing a correction

**Record the Agent choosing a correction preset, reviewing the customer message and sending the request. Show the waiting state.**

“The Agent selects the information that needs to be corrected, reviews the message, and sends the update request. The application then waits for the customer’s response.”

**Record the Customer portal notification, correction notice and correction form. Update the incorrect ID number or other requested field. For a photo correction, show both photo inputs and their feedback.**

“The customer can open the notification to see the request. The correction notice explains what needs to be changed.

Here, the customer updates the incorrect information and submits it. If a replacement photo is needed, the customer can choose the correct side and check its quality message before sending the update.”

**Record the application returning to the Agent queue and its updated result. Keep an Agent or Manager session open during this step.**

“The updated application returns for review, and the document check runs automatically again. The Agent can inspect the corrected details and decide whether the application is ready to proceed.”

## Groupmate 3 — Provider update and reports

**Record the Agent’s status selection, provider reference and proof attachment using fictional information. Then show the corresponding Customer status.**

“Once the requirements are ready, the Agent can record the provider reference and supporting proof. When the provider gives an update, the Agent records that status so the customer can follow the progress from their account.”

**Record Reports, choose a date or month, then open Print Report and the downloaded report.**

“The reports help staff review applications for a selected period. The printed report and downloaded report show the same filtered information.”

## Groupmate 3 — Manager Dashboard

**Record the Manager overview, application list and Agent management. Open Website CMS, change a sample announcement or banner, then show it on the public website.**

“The Manager can monitor applications and manage the Agents who handle them. From the application list, the Manager can review progress and adjust assignments when needed.

The Manager can also update the public website. For example, an announcement or banner can be changed here and then viewed on the homepage.”

## Groupmate 3 — Administrator and closing

**Record the Admin account-management area, maintenance control and activity records. Finish on the public homepage.**

“The Administrator handles account management and system settings. Maintenance controls help the team manage periods when online applications are temporarily unavailable, while the activity records help them review what has happened in the system.

That completes the application journey, from selecting a plan and submitting requirements to receiving corrections and following the application’s progress. Thank you.”
